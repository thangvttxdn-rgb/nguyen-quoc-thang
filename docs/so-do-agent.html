Năm lớp phòng thủ

Không lớp nào hoàn hảo một mình. Lệnh nguy hiểm phải lọt qua tất cả các lớp mới gây hại được.

Lớp 1 · guard.py

Hook soi nội dung

  • Cấm mọi kiểu rm -rf, kể cả rm -r -f, rm -fr
  • Cấm SHUTDOWN, DROP DATABASE
  • Cấm ghi file ngoài dự án và mật khẩu viết thẳng
  • Hỏi trước câu SQL ghi hoặc đổi cấu trúc

Giới hạn: soi theo chữ nên đôi khi chặn nhầm, ví dụ commit message có chữ SQL.

Lớp 2 · settings.local.json

Luật phân quyền

  • Tự chạy: test, lint, git chỉ đọc
  • Hỏi: sửa file, commit, push, cài thư viện, sqlcmd
  • Cấm: force-push, reset --hard, đọc .env

Giới hạn: khớp mẫu chữ, biến thể khác cách viết có thể lọt.

Lớp 3 · connection.py

Code truy cập CSDL

  • fetch_all chỉ nhận một câu SELECT
  • execute_write chỉ INSERT hoặc UPDATE có WHERE
  • Không có đường nào để DELETE

Giới hạn: chỉ bảo vệ code đi qua module này.

Lớp 4 · SQL Server

Tài khoản CSDL

  • Agent: chỉ db_datareader
  • Ứng dụng: không cấp quyền DELETE

Lớp chắc chắn nhất. Cần anh cấu hình trên máy chủ.

Lớp 5 · GitHub Actions

CI tự động

  • ruff với luật bảo mật S
  • pytest trên Python 3.11 và 3.13
  • Chạy mỗi PR và mỗi lần đẩy lên main

Bắt lỗi sau khi code đã viết, không chặn lệnh lúc agent chạy.

Khi nào một việc được tính là xong

1 · pytest -qToàn bộ test xanh 100%.
2 · ruff checkKhông phát sinh lỗi lint mới.
3 · todo.md + MEMORY.mdTrạng thái đã cập nhật, bài học quan trọng đã ghi lại.

Ghi chú

  • Tình huống "Tác vụ thật có vòng lặp" dùng kết quả minh họa (lần đầu 1 test đỏ) để cho thấy Verifier đẩy việc quay lại bước lập kế hoạch.
  • Hook chạy trước luật phân quyền: theo tài liệu Claude Code, hook PreToolUse được gọi trước khi xét quyền của công cụ.
  • Phân quyền tài khoản trên SQL Server (lớp 4) chưa được cấu hình; sơ đồ thể hiện trạng thái mong muốn.
